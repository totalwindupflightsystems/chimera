# Chimera v0.3.0 — release notes

**2026-11-21** · previous release **v0.2.9** (2026-10-30) · 25 product commits

v0.3.0 is a reliability release with one new serving surface. The theme is *the
run finishes*: a drained provider account, a dead aggregator and a hidden retry
ladder each used to end a deliberation without an answer after every worker had
already been billed. Each of those paths now either succeeds elsewhere or
answers a machine-readable error that names what was skipped and why.

## Added

- **`GET /metrics`** — Prometheus text-format 0.0.4 on the API listener:
  request counter, latency histogram and a by-cause error counter. Labels are
  route templates, unmatched requests collapse to `<unmatched>`, and the scrape
  endpoint is excluded from its own counters. Pure-ASGI middleware, so SSE
  bodies are never re-framed.
- **Rank-then-fuse aggregation (opt-in)** — `rank: true` plus `kappa`
  (default 3) and an optional `rank_model` score every upstream output with one
  cheap call and merge only the top-`kappa`. Default `false`. A failed or
  unparseable scorer pass feeds every output and records `rank_error`, so a
  cheap pass can never silently drop a worker's work.
- **Ordered merge fallback chain** — `aggregator_fallbacks` (defaults-level and
  per-formation) walks an ordered list of catalog models instead of retrying one
  substitute. Bounded at 4 real calls per run; a quota-class failure demotes that
  account's entries rather than dropping its siblings; omitted key inherits the
  defaults, an explicit empty list disables. `trace.aggregator_model` now names
  the model that actually served the merge.

## Fixed

- **Quota-exhausted providers no longer sink a run** (DF-CHIMERA-V2-130).
  Selection consulted credential presence, not balance. It now consults the
  health snapshot and a new 15-minute `quota` block class at the start of every
  run, remaps worker *and* merge-stage work onto the next healthy candidate, and
  answers a `503` with `error.type: no_healthy_candidate` naming every skipped
  provider/model/failure-class when nothing healthy is left.
- **Locked models stop silently swallowing overrides** (DF-CHIMERA-V2-131). A
  structured `discarded_overrides` record (field, locked value, requested value)
  now rides the success and refusal surfaces, including 502/503 paths.
- **Bad `allowed_models` ids answer 400, not a plain-text 500**
  (DF-CHIMERA-V2-110), validated before the dispatcher so a rejected request
  costs zero upstream calls.
- **Malformed `X-Chimera-Timeout` headers answer 400** (DF-CHIMERA-V2-117),
  naming the offending pair; a mixed header applies no part at all.
- **One retry budget** (DF-CHIMERA-V2-126). `num_retries=0` removes LiteLLM's
  hidden ladder: `max_attempts` 1/3/5 cost 3/9/15 upstream requests before and
  costs exactly one each now.
- `chimera serve` honours the global `--config` flag (119); an in-process
  `Engine` applies `observability.log_level` / `use_stdout` (113);
  `credential_sources` reports the configured source (REVIEW-08); `CHIMERA_PORT`
  governs the container port again (README-13).

## Changed

- `/v1/health` and `/v1/health/ready` are bounded by
  `server.health_endpoint_budget_s` (default 1.5s) over a
  stale-while-revalidate single-flight probe: 11.028s → 1.502s and 11.012s →
  1.501s against a hanging provider, with `stale: true` and per-provider `age_s`
  keeping partial answers honest (PERF-1).
- Explicit formations skip the dispatcher LLM call: one measured run went
  25997ms → 10418ms and dropped $0.0013677 of dispatcher spend. A formation can
  set `dispatch_prompts: true` to opt back in (PERF-2).
- `chimera.yaml.example` returns to its 120-line minimal budget; fleet-operator
  settings moved to `chimera.yaml.fleet`, and the example gains the
  `quick-panel` formation, the `quick` alias used by the 9router upstream lane,
  a pro-tier `panel` escalation, and an auth block that ships disabled.
- The integration CI leg is non-blocking on the unfunded provider account
  (INT-CI-022) and annotates a non-billing failure as a code regression instead
  of mistaking it for one.
- gitlab and github `main` are reconciled onto a single mainline.

## Upgrade notes

- New optional config keys — no migration required, all default to existing
  behaviour: `aggregator_fallbacks`, `rank`, `kappa`, `rank_model`,
  `dispatch_prompts`, `server.health_endpoint_budget_s`.
- Retry semantics changed: `max_attempts` is now the only ladder. A caller that
  passes its own retry knobs is logged (`gateway_caller_retry_ignored`).
- Three request-validation paths that used to succeed silently now answer `400`
  (unknown `allowed_models` id, malformed `X-Chimera-Timeout`, unparsable value).
  A client that was relying on a silent drop will now see the error.

## Known gaps at release time

  (`402 Insufficient Balance`, tracked as INT-CI-022 — funding is an owner
  decision). It does not run on tag pushes.
- An auto-formation run whose *dispatcher* provider is quota-dead still answers
  an opaque JSON `500` rather than a classified error, while explicit formations
  can now answer `503 no_healthy_candidate`. Filed as a release finding rather
  than fixed in this cut.
- The deployed instance is behind this tag; deployment is tracked separately.
